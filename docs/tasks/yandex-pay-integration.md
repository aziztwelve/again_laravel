# Задача: тестовая интеграция Яндекс Пэй для оплаты заказов

**Статус:** Реализована, ожидает включения sandbox-реквизитов и ручного сценария в кабинете
**Дата:** 2026-08-24
**Витрина:** `again_front`
**Backend:** `lara_admin`

## Описание

Интегрировать тестовую оплату Яндекс Пэй в сценарий:

```text
Сайт -> Checkout -> Выбор способа оплаты -> Яндекс Пэй -> Pay или Сплит
```

Сейчас оплата Яндекс Пэй не подключена. Нужно добавить её рядом с текущей
интеграцией CloudPayments, не меняя существующие способы оплаты и не обходя
серверную проверку заказа.

## Планируемый результат

В checkout покупатель может выбрать способ оплаты **Яндекс Пэй**. На форме
Яндекс Пэй доступны оба сценария:

- полная оплата через Яндекс Пэй (`CARD`);
- оплата частями через **Сплит** (`SPLIT`).

После успешной оплаты заказ получает статус `paid`, создаётся ровно одна
запись `Payment` и запускается существующий post-payment процесс. Неуспешная
или прерванная оплата не оплачивает заказ и позволяет повторить попытку.

## Выбранная схема

Используем базовую механику полной оплаты через Yandex Pay Web SDK v4 и
Merchant API. Рекуррентные платежи и двухстадийную оплату в первую поставку
не включаем.

```text
Checkout -> POST /api/public/orders -> заказ pending
       -> frontend создаёт сессию Yandex Pay Web SDK (env=SANDBOX)
       -> POST backend /v1/orders в sandbox.pay.yandex.ru
       -> backend возвращает paymentUrl
       -> SDK открывает форму Яндекс Пэй
       -> покупатель выбирает CARD или SPLIT
       -> Yandex Pay webhook (JWT ES256)
       -> проверка подписи, merchantId, заказа и суммы
       -> CAPTURED: Payment=completed, Order.payment_status=paid
       -> OrderPaid -> существующий post-payment процесс
```

SDK callback и redirect используются только для интерфейса. Источником истины
для статуса оплаты является проверенное уведомление Яндекс Пэй либо серверный
запрос статуса заказа через Merchant API, если webhook временно недоступен.

## Контракт и безопасность

| Элемент | Решение |
|---|---|
| Среда первой поставки | Только `SANDBOX`: API `https://sandbox.pay.yandex.ru`, SDK с `PaymentEnv.Sandbox`. |
| SDK | Подключать актуальный скрипт `https://pay.yandex.ru/sdk/v1/pay.js`; не копировать, не бандлить и не проксировать. |
| API-аутентификация | Серверный Merchant API key только в `.env`; ключ не возвращается во frontend и не попадает в git. В sandbox ключ равен Merchant ID по документации. |
| Сумма | Берётся из сохранённого заказа на backend. Клиентские сумма и состав корзины не являются источником истины. |
| Идентификатор | `orderId` Yandex Pay должен однозначно ссылаться на локальный заказ/платёж и быть идемпотентным. Повторное создание не должно создавать второй локальный платёж. |
| Доступные методы | Для обоих сценариев передавать `availablePaymentMethods: ["CARD", "SPLIT"]`; для выбранного варианта задавать `preferredPaymentMethod`. Не принимать произвольное значение от клиента. |
| Корзина | Передавать все товары и доставку отдельной позицией. Суммы позиций, количество и `cart.total.amount` должны совпадать с заказом. |
| Webhook | Принимать `application/octet-stream`, извлекать JWT из тела и проверять ES256 до разбора payload. Проверять `merchantId`, order ID, сумму и допустимый переход статуса. |
| Повторы | Webhook обрабатывать идемпотентно. Повторный `CAPTURED` не создаёт второй `Payment`, доставку или событие оплаты. На успешно обработанное уведомление отвечать HTTP 200. |
| Фискализация | Передать `fiscalContact`, `cart`, `currencyCode`, `availablePaymentMethods` и `cart.items[].receipt.tax`, если в кабинете Яндекс Пэй включена онлайн-касса. Ставка НДС должна быть согласована с бухгалтерией. |
| CSP | Разрешить для витрины `script-src`, `frame-src`, `img-src`, `connect-src: https://pay.yandex.ru`; не добавлять небезопасные wildcard-исключения. |

## Backend-работы

- Добавить конфигурацию `yandex_pay` с флагом включения, sandbox/production
  URL, Merchant ID, API key и callback URL.
- Добавить провайдер/сервис создания заказа Yandex Pay через `POST
  /api/merchant/v1/orders`.
- Добавить endpoint для создания Yandex Pay intent по `viewToken` только для
  неоплаченного заказа, с повторным использованием существующей попытки при
  повторном запросе.
- Сформировать `cart` из серверных позиций заказа, включая скидки и доставку,
  без доверия к данным checkout.
- Сохранить `provider_payment_id`, `provider_data` и внешний ID заказа в
  `payments` или согласованном отдельном поле/таблице.
- Добавить webhook `/v1/webhook` или согласованный route на домене API. Учесть,
  что в кабинете Callback URL задаётся без суффикса `/v1/webhook`, который
  добавляет Яндекс Пэй.
- Реализовать обработку `ORDER_STATUS_UPDATED` для `CAPTURED` и `FAILED`.
  `PENDING` не считать успешной оплатой.
- Добавить запрос статуса заказа Yandex Pay для сверки и fallback, не полагаться
  только на браузерный redirect.
- Добавить точечные feature/unit-тесты для подписи JWT, проверки заказа и суммы,
  идемпотентности webhook, статусов `CAPTURED`/`FAILED` и повторного intent.
- Обновить публичный контракт заказа и админские отображения способа оплаты,
  если текущие перечисления payment methods требуют этого.

## Frontend-работы

- Добавить выбор Яндекс Пэй в checkout без удаления CloudPayments.
- Подключать кнопку/виджет Yandex Pay только при серверном флаге доступности и
  наличии публичных параметров интеграции.
- Инициализировать Web SDK v4 с `env=SANDBOX`, валютой `RUB`, фактической суммой
  заказа и методами `CARD`/`SPLIT`.
- По `onPayButtonClick` получать от backend ссылку `paymentUrl` и передавать её
  SDK; не создавать заказ Yandex Pay напрямую из браузера.
- После redirect/polling обновлять страницу заказа и показывать состояния
  «ожидание», «оплачено», «не оплачено» и возможность повторить оплату.
- Не показывать Merchant API key и не принимать решение об оплате по callback
  SDK.

## Настройка тестовой среды

В кабинете Яндекс Пэй:

1. Подать заявку и дождаться активации тестовой среды.
2. Включить **Тестовые данные**.
3. Проверить тестовые Merchant ID и Merchant API key. Для sandbox ключ API
   должен соответствовать Merchant ID.
4. Указать тестовый Callback URL без `/v1/webhook`, например:
   `https://againdev3.ru`.
5. После реализации проверить, что ссылка оплаты содержит sandbox-домен.

Секреты добавляются только на сервере. `.env` не изменять в git и не передавать
во frontend.

## Реализация

- Backend: `YandexPayService`, intent/status API и JWT ES256 webhook готовы;
  проверка суммы и статуса всегда идёт через Merchant API.
- Витрина: доступный по серверному флагу Web SDK v4 загружается с
  `pay.yandex.ru`, создаёт order только в `onPayButtonClick` и после redirect
  несколько раз сверяет статус с backend.
- Перед включением необходимо внести на сервере `YANDEX_PAY_ENABLED=true`,
  `YANDEX_PAY_ENV=sandbox`, `YANDEX_PAY_MERCHANT_ID`, `YANDEX_PAY_API_KEY` и
  (для кассы) согласованный `YANDEX_PAY_RECEIPT_TAX`. Затем очистить config
  Laravel и указать в кабинете callback `https://againdev3.ru`.
- Nginx обязан направлять `POST /v1/webhook` в Laravel (см. deploy-runbook);
  без этого callback попадёт в витрину, а не в обработчик подписи.

## Тест-план

- **Яндекс Пэй:** создать заказ из checkout, выбрать Яндекс Пэй/CARD, успешно
  завершить sandbox-оплату; ожидается `CAPTURED`, локальный заказ `paid` и один
  completed `Payment`.
- **Сплит:** создать заказ из checkout, выбрать Сплит; ожидается успешная
  оплата через форму Yandex Pay и тот же локальный результат `paid`.
- **Отказ:** получить `FAILED`; заказ не становится `paid`, повторная попытка
  доступна.
- **Отмена/закрытие формы:** заказ остаётся неоплаченным, технические данные
  не показываются покупателю.
- **Повтор webhook:** повторить одинаковое уведомление; нет второго платежа,
  события оплаты или доставки.
- **Неверная подпись JWT:** endpoint отвечает ошибкой, заказ и платеж не
  изменяются.
- **Неизвестный заказ или несовпадение суммы:** webhook отклоняется с корректным
  `reasonCode`, локальный заказ не оплачивается.
- **Повторное нажатие оплаты:** не создаются дубли локальной попытки и заказа
  Yandex Pay.
- **Фискализация:** если касса включена, в запросе присутствуют контакт,
  позиции, доставка, итоги и ставка НДС; после успешной оплаты чек формируется.
- **Smoke:** checkout, переход на sandbox payment URL, webhook, страница заказа,
  отсутствие регрессии CloudPayments.

## Что не входит в первую поставку

- боевой запуск без отдельной проверки кабинета и реквизитов;
- рекуррентные платежи и сохранение карт;
- двухстадийные платежи, capture/void;
- автоматические возвраты через API;
- QR-код Яндекс Пэй и офлайн-касса;
- маркированные товары до подтверждения ограничений фискализации;
- миграция или отключение CloudPayments.
