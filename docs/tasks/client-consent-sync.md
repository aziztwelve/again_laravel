# Четыре согласия клиента

Код подготовлен локально. Деплой, миграция и серверные проверки выполняются
только по отдельной команде пользователя, по `docs/deploy-runbook.md`.

## Поведение

- Карточка клиента и формы создания/редактирования показывают четыре статуса:
  политика конфиденциальности, обработка ПД, оферта, рекламная рассылка.
- «Уведомления о заказе» удалены из этого блока. Существующее поле
  `messenger_subscription` и его данные сохраняются; формы больше его не отправляют.
- Чекаут отправляет четыре значения вместе с заказом. Backend сохраняет их
  в связанной записи клиента в транзакции заказа, для гостя и авторизованного клиента.
- ЛК загружает и сохраняет те же четыре поля. Изменения видны при следующей
  загрузке карточки/ЛК. Простое переключение без сохранения не изменяет БД.
- Первые три галочки обязательны для отправки формы витрины, рассылка добровольна.
  В чекауте рассылка отражает сохранённое значение авторизованного клиента,
  у гостя изначально выключена. Первые три галочки чекаута требуют подтверждения.
- Запросы старой витрины без полей согласий сохраняют прежние значения.
  Переданное `false` для рассылки сохраняется. Админ может менять каждый статус.
- Дата ПД заполняется при подтверждении покупателем, сохраняется при повторном
  подтверждении и очищается при снятии согласия. Админские правки не создают
  фиктивную дату подтверждения самим покупателем.

## Проверка при деплое

1. Применить миграцию `2026_10_12_000001_add_policy_and_oferta_consents_to_clients`.
2. На сервере в подготовленной тестовой БД выполнить
   `php artisan test --filter ClientConsentSyncTest` (использует DatabaseTransactions).
3. Собрать обе фронтенд-части по runbook.
4. Проверить четыре статуса в карточке клиента и обеих формах админки.
5. На тестовом клиенте сохранить ЛК с рассылкой и без неё, перезагрузить ЛК
   и карточку; проверить совпадение всех четырёх полей.
6. Оформить тестовые заказы гостем и авторизованным клиентом. Проверить согласия
   именно у связанного с заказом клиента. Ошибка оформления не должна менять согласия.
7. Изменить статусы в админке и проверить их после повторной загрузки ЛК.
   Старый флаг уведомлений о заказе должен остаться прежним.
