# Ручное закрепление клиентов в сегментах

В карточке любого сегмента доступна кнопка «Добавить клиента вручную».
Для клиента, который уже входит по условиям, в таблице есть «Закрепить вручную».
Колонка «Добавление» показывает «По условиям» или «Вручную · закреплён».

Ручное добавление записывает `client_segment.is_manual = true`.
Автоматический пересчёт добавляет подходящих клиентов с `false` и сохраняет
всех закреплённых вручную. Работает и при одиночном, и при массовом пересчёте,
включая сегменты с ручной частотой пересчёта и сохранёнными условиями.

DELETE `/api/segments/{segment}/clients` теперь снимает ручное закрепление.
Клиент, подходящий по условиям, остаётся с `is_manual = false`; остальные
удаляются из сегмента. `removed_count` сообщает реальное число вышедших.
Для списка без условий снятие закрепления удаляет клиента сразу.
Постоянное исключение клиента из автоматического сегмента не добавлено.

POST того же endpoint закрепляет выбранные client_ids. Повторный POST
не создаёт дубликат и сохраняет первоначальную дату добавления.
Изменение состава доступно только сотрудникам (User), а не покупателям.
Удалённые клиенты, пустые списки, дубли и несуществующие ID отклоняются.

Промокоды выдаются при добавлении. При снятии закрепления они остаются,
если клиент продолжает входить по условиям или получает код через другой
сегмент. Доступ к акциям проверяется по текущему составу активных сегментов.

Миграция `2026_10_14_020000_add_manual_membership_to_client_segment`:
старые участники сегментов с частотой manual помечаются ручными, чтобы
не потерять исторические ручные добавления. Старые участники автоматических
сегментов остаются автоматическими: прежняя схема не хранила происхождение.

Изменения состава и пересчёт сериализованы блокировкой строки сегмента
в транзакции. Это защищает закрепление от одновременного пересчёта.

## Проверка

Только на сервере, с обновлённой отдельной БД testing:

```bash
DB_DATABASE=testing php artisan migrate --force
php artisan test --filter 'SegmentManualMembershipTest|SegmentRecalculationTest|PromotionSegmentsTest|PromotionStackingTest'
```

14 октября 2026: 45 тестов / 175 assertions прошли, включая 26 новых сценариев.
Проверены значения ниже, ровно на и выше порога 30 000 ₽.
В браузере проверены поиск клиента без покупок, ручное добавление в
автоматический сегмент, сохранение после пересчёта и снятие закрепления.
Временные клиент и сегмент удалены.
