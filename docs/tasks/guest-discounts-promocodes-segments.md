# Задача: Скидки, промокоды и сегменты для гостевого пользователя

**Статус:** Реализация подготовлена локально  
**Дата:** 2026-07-09

**Обновление 2026-07-09:** добавлены backend-миграция и логика аудитории
`authorized / guest / all` для скидок, промокодов и сегментов; добавлены поля в
формы и таблицы админки. Локальные серверы не запускались.

## Описание

Добавить функционал выбора аудитории для скидок, промокодов и сегментов:

- авторизованные пользователи
- гостевые пользователи
- все пользователи

Сейчас в логике скидок, промокодов и сегментов нет отдельной поддержки гостевого пользователя.

---

## Сценарий

Сайт → админка → Скидки и Промокоды

Администратор при создании или редактировании скидки, промокода или сегмента выбирает, для какой аудитории правило должно работать.

---

## Целевой результат

В логике скидок, промокодов и сегментов появляется единое поле выбора аудитории.

### Для скидки

При создании и редактировании скидки добавить поле выбора:

- для авторизованного пользователя
- для гостевого пользователя
- для всех

### Для промокода

При создании и редактировании промокода добавить поле выбора:

- для авторизованного пользователя
- для гостевого пользователя
- для всех

### Для сегмента

При создании и редактировании сегмента добавить поле выбора:

- для авторизованного пользователя
- для гостевого пользователя
- для всех

---

## Предлагаемая модель данных

Добавить единое поле `customer_type` или аналогичное поле в сущности скидок, промокодов и сегментов.

Возможные значения:

| Значение | Описание |
|----------|----------|
| `authorized` | Только авторизованный пользователь |
| `guest` | Только гостевой пользователь |
| `all` | Все пользователи |

Рекомендуемое значение по умолчанию: `all`, чтобы существующие скидки, промокоды и сегменты продолжили работать без изменения поведения.

---

## Бизнес-логика

1. Если правило настроено для `authorized`, оно применяется только к пользователю с авторизацией.
2. Если правило настроено для `guest`, оно применяется только к гостевому пользователю.
3. Если правило настроено для `all`, оно применяется и к авторизованному, и к гостевому пользователю.
4. Проверка аудитории должна выполняться в момент получения доступных скидок/промокодов/сегментов и перед финальным применением к заказу.
5. Для гостевого пользователя нельзя полагаться на `user_id`; определение должно идти по факту отсутствия авторизованного пользователя в checkout/API-запросе.

## Чек-лист проверки

- [ ] Создать скидку для авторизованных пользователей → гостю она недоступна
- [ ] Создать скидку для гостевых пользователей → авторизованному пользователю она недоступна
- [ ] Создать скидку для всех → доступна гостю и авторизованному пользователю
- [ ] Создать промокод для авторизованных пользователей → гость не может его применить
- [ ] Создать промокод для гостевых пользователей → авторизованный пользователь не может его применить
- [ ] Создать промокод для всех → доступен гостю и авторизованному пользователю
- [ ] Создать сегмент для авторизованных пользователей → гость не попадает в сегмент
- [ ] Создать сегмент для гостевых пользователей → авторизованный пользователь не попадает в сегмент
- [ ] Создать сегмент для всех → сегмент работает для обеих аудиторий
- [ ] Существующие скидки, промокоды и сегменты после миграции имеют значение `all`
- [ ] Финальная проверка при оформлении заказа не позволяет применить правило не для своей аудитории
