# Задача: Полный импорт базы отзывов из CSV на сайт

**Статус:** Решения утверждены — в реализации
**Дата:** 2026-07-09
**Раздел сайта:** Карточка товара → блок «Отзывы» (`again_front`), главная → «Отзывы»
**Раздел админки:** Отзывы (`again_dashboard`)
**Источник:** `reviews-15.05.2026.csv` (выгрузка отзывов, UTF-16 LE, tab-separated)

---

## Описание

**ТЗ:** провести полный экспорт базы отзывов на сайт.
**План-результат:** в разделе «Отзывы» на сайте появились **все** отзывы, а не
только те, что заливали ранее для теста.
**Факт на сейчас:** отзывы залиты **частично**.

### Что реально в данных (проверено на сервере 2026-07-09)

- В CSV **657** отзывов (не 939 — многострочные комментарии завышают счёт строк).
  Колонки (tab-separated): `Дата и время публикации`, `Имя автора`,
  `E-mail автора`, `Название Товара`, `ID Товара`, `Артикул Товара`,
  `Ссылка на Товар`, `Комментарий`, `Рейтинг`, `Ответ менеджера`,
  `Имя менеджера`, `Дата и время ответа`, `Опубликованность`, `Спам`.
- В БД **уже 595 отзывов** (не «5 тестовых»), все `is_published = true`,
  9 `review_responses`. Все привязаны к `reviewable_type = App\Models\Product`.
- Пересечение по префиксу текста комментария: из 645 уникальных комментариев CSV
  **~502 уже есть** в БД, **~143 отсутствуют**. То есть нужен **до-импорт
  недостающих**, а не заливка с нуля.
- Даты в CSV в ISO-формате `2024-05-19 18:36:28` (старая команда `import:reviews`
  парсит только `d.m.Y H:i` — **несовместимо**, надо чинить парсер).
- `Спам` во всём файле = «Нет»; `Опубликованность`: 626 «Да», 31 «Нет».
- Рейтинг: 560×5, 20×4, 9×3, 4×2, 4×1 и **60 пустых** (старая команда такие
  строки пропускает — теряем до-импорт).
- Ответ менеджера присутствует в 11 строках; `Имя менеджера` хранить негде.

### Ключевая проблема — маппинг товаров

**Ссылки/артикулы из CSV НЕ совпадают с тем, что в БД.** В CSV ссылки вида
`/product/good-night-again`, `/product/love-again`, `/product/box-again` —
таких `products.slug` в базе **нет**. Актуальные slug'и: `menstrualnye-trusy-love-again`
и т.п. Плюс в каталоге **много дублей** товаров с одинаковым именем (по 3-5 копий
«Менструальные трусы Love AGAIN» с разными id и активностью).

## Принятые решения

- **Маппинг товара (#1):** сопоставлять по **имени AGAIN-линейки** (нормализованно:
  `love/save/passion/sexy/body/box/set`), а не по slug/артикулу из CSV (они
  устарели). Для каждого имени — фиксированный **целевой активный товар витрины**
  (таблица выше). Захардкодить карту `имя → product_id` в команде и логировать
  каждое сопоставление. Ссылку/артикул из CSV использовать только как доп. проверку.
- **Дубли товаров (#2):** отзывы льём **только на активный товар**, который реально
  открывается на витрине по `/product/{slug}`. **Решение: да** — перепривязываем
  старые отзывы с неактивных/удалённых дублей (#48 Sexy, #37 Body, #15 BOX) на
  активные товары витрины (#252, #241, #219), иначе они не видны покупателю.
- **Идемпотентность (#3):** дедуп-ключ = `reviewable_id` + `client_id` (или email) +
  нормализованный `content` (или его хэш) + `created_at`. Повторный запуск не плодит
  дубли. Старой команде идемпотентности не хватает — это причина частичной заливки.
- **client_id (#4):** `reviews.client_id` — **NOT NULL FK**. Стратегия:
  1. искать `Client` по `email` из CSV;
  2. если нет — **создавать гостевого клиента** (email + имя автора из CSV).
     **Решение: создавать гостевых клиентов.** Идемпотентно по email
     (`firstOrCreate`), чтобы повторный запуск не плодил клиентов.
- **Пустой рейтинг (#5):** 60 строк без рейтинга. **Решение: пропускать** такие
  строки (логировать в сводку `skipped_no_rating`).
- **Публикация (#6):** `Опубликованность = Да` → `is_published/is_verified = true`,
  `status = published`, `published_at` = дата из CSV. Учесть **boot-хук** модели
  `Review` (`creating` форсит unpublished) — публиковать через `update()` после
  создания либо отдельным проходом. `Спам = Да` → `is_spam = true` (в CSV сейчас
  таких нет).
- **Ответ менеджера (#7):** `Ответ менеджера` → `review_responses.content`,
  `Дата ответа` → `created_at`, `user_id = 1` (админ). `Имя менеджера` **не храним**
  (нет колонки; имя берётся из связанного User). При повторном импорте — не дублировать.
- **Формат/кодировка (#8):** читать UTF-16 LE, разделитель `\t`, парсить дату
  и ISO (`Y-m-d H:i:s`), и старый `d.m.Y H:i`.
- **Длина текста (#9):** импорт пишет напрямую через Eloquent, минуя лимит API
  `max:200` — комментарии длинные (до ~1525 симв. в БД уже есть), колонка `content`
  = `text`, ограничений нет.
- **Фронты (#10):** витрина — `again_front` (блок «Отзывы» на карточке товара,
  `GET /api/reviews?product_id=`), админка — `again_dashboard`.

---

- **Товары без совпадения (#11):** Comfort AGAIN, Трусы слипы Soft AGAIN,
  Набор слипов Soft SET (3 отзыва) — товаров в БД нет. **Решение: пропускать**
  (логировать `skipped_no_product`).

## Решения по открытым вопросам (утверждены 2026-07-09)

1. Перепривязка старых отзывов с неактивных дублей на активные — **да**.
2. client_id новых отзывов — **создавать гостевых клиентов** из CSV (по email).
3. Пустой рейтинг (60 строк) — **пропускать**.
4. Товары без совпадения (Comfort/Soft/Soft SET) — **пропускать**.

## План реализации

1. **Новая artisan-команда** `import:reviews:full` (не трогаем старую `import:reviews`,
   чтобы не сломать историю), либо переписать старую с флагом `--dry-run`.
   Аргумент — путь к CSV, по умолчанию `storage/imports/reviews-15.05.2026.csv`.
2. Чтение UTF-16 LE → UTF-8, tab-separated, устойчивый парсер дат (ISO + `d.m.Y H:i`).
3. Карта `имя AGAIN → product_id` (решение #1) + fallback-логирование несопоставленных.
4. Резолв `Client` по email (решение #4).
5. Идемпотентная вставка `Review` (решение #3) с корректной публикацией (решение #6,
   учесть boot-хук). Ответ менеджера — `ReviewResponse` (решение #7).
6. `--dry-run`: печатать сводку (сколько создастся/пропустится/не сопоставлено) без
   записи в БД. Прогон на сервере сначала в dry-run, ревью сводки, затем реальный импорт.
7. **Тесты** (`tests/Feature/...`): маппинг имени → товар; идемпотентность (повторный
   запуск не плодит дубли); публикация/спам-флаги; ответ менеджера; пустой рейтинг.
8. Смоук на витрине: `GET /api/reviews?product_id={id}` возвращает возросшее число
   опубликованных отзывов по каждому AGAIN-товару.

### Затрагиваемые сущности (факт)

- `app/Console/Commands/Import/ImportReviewsFromCsv.php` — существующая команда
  (`import:reviews`); путь захардкожен, парсер дат несовместим, нет идемпотентности,
  не пишет `is_spam`, пропускает пустой рейтинг и ненайденных клиентов.
- Модель `app/Models/Review/Review.php` — `$guarded=['id']`, boot-хук `creating`
  форсит `is_published=false/status=new`; `updating` публикует при `is_published=true`.
- Модель `app/Models/Review/ReviewResponse.php` — ответы менеджера (`user_id`, `content`).
- Таблицы: `reviews` (`client_id` NOT NULL, `content` text, `rating` tinyint,
  `status`, `is_verified`, `is_published`, `is_spam`, `published_at`),
  `review_responses`.
- Витрина: `again_front/components/Product/Reviews.vue` → `GET /api/reviews?product_id=`;
  `again_front/components/Home/Reviews.vue` → `GET /api/reviews/home-random`.
