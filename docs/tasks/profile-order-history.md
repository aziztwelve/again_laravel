# История заказов в профиле

Реализован выбранный пользователем макет: на компьютере состав и расчёт суммы слева, доставка и действия справа; на телефоне блоки идут вертикально. Все заказы открыты по умолчанию, каждый можно свернуть.

`GET /orders/user` теперь отдаёт `OrderHistoryResource` с данными чека: позиции и количество по штукам, итоговые/исходные суммы строк, общая скидка без повторного сложения промокода, стоимость доставки, сумма заказа, оплата сертификатом, адрес с квартирой, служба доставки и трек. Фото берётся у варианта, затем у товара, основное имеет приоритет. Внутренние комментарии и данные интеграций в ресурс не включены. Сохранены фильтр текущего клиента, сортировка новых заказов первыми и формат pagination; per_page валидируется, максимум 100.

Витрина загружает заказы страницами по 10. Ошибка загрузки не выдаётся за пустую историю. Действие «Повторить заказ» требует подтверждения, проверяет текущие товары, варианты, цвета и суммарное количество с корзиной. Все изменения готовятся до записи в корзину; при недоступной позиции корзина не меняется. Существующая корзина сохраняется, подарки из старого заказа исключаются, прошлые промокоды и цены не переносятся. Пользователь получает ссылку на checkout, где повторно рассчитываются скидки и доставка.

Миграции и сидеры не нужны. Нужен совместный деплой Laravel и Nuxt: формат истории обновлён в обоих проектах.

## Проверка после отдельной команды на деплой

Деплой выполняется по `docs/deploy-runbook.md`. До него выполнены только статические проверки; серверные тесты и визуальная QA ожидаются.

На сервере:

- Laravel: `php artisan test --filter OrderHistoryResourceTest` (модели создаются в памяти, без RefreshDatabase).
- Nuxt: `npm test -- tests/orderHistory.test.ts`.
- Визуальная и функциональная проверка `/profile/history`: план находится в `again_front/design-qa.md` (пока `final result: blocked`, поскольку приложение ещё не развёрнуто для проверки).
