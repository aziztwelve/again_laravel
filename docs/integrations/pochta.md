# Почта России (API «Отправка»)

В чекауте четыре способа доставки: «Почта РФ: в отделение», «Почта РФ: Курьер», «Почта РФ: международная в пвз»,
«Почта РФ: международная курьер». Сейчас сделан **первый этап**: показать способы, посчитать цену и срок,
сохранить выбор в заказе. Создание отправлений, печать форм и отслеживание — следующие этапы (см. ниже).

Код: `app/Services/Delivery/PochtaDeliveryService.php`, клиент `Delivery/Pochta/PochtaClient.php`,
контроллер `Api/Delivery/PochtaDeliveryController.php`, витрина `again_front/composables/usePochtaCheckout.ts`
и блок «Почта России» в `components/Checkout/Delivery.vue`.

Секреты в документацию не записываем: только имена переменных и места, где они лежат.

## Доступ

Пока способы не открыты всем, их видят только покупатели с email из `POCHTA_TESTER_EMAILS` (через запятую, нужно войти
в аккаунт). Для остальных способы скрыты из списка, а расчёт, поиск отделений и оформление заказа отвечают отказом.
Открыть всем: `POCHTA_PUBLIC=true` в `.env` сервера и `php artisan optimize:clear`.

## Подключение

| Переменная `.env` | Что это |
|---|---|
| `POCHTA_ENABLED` | `true` включает интеграцию, без неё расчёт отвечает 503 |
| `POCHTA_TOKEN` | токен приложения (личный кабинет otpravka.pochta.ru → настройки) |
| `POCHTA_LOGIN`, `POCHTA_PASSWORD` | логин и пароль к API (из passport.pochta.ru) |
| `POCHTA_PUBLIC`, `POCHTA_TESTER_EMAILS` | открыть способы всем / список email тестировщиков |
| `POCHTA_INDEX_FROM` | индекс места приёма; пусто — берётся точка сдачи из профиля (сейчас 188513, Разбегаево) |
| `POCHTA_BASE_URL` | по умолчанию `https://otpravka-api.pochta.ru` |

Заголовки запросов: `Authorization: AccessToken <токен>` и `X-User-Authorization: Basic base64(логин:пароль)`.
Настройки из таблицы `delivery_services_settings` (`service_name = 'pochta'`) перекрывают `.env` и `config/services.php`.

После выкладки: `php artisan migrate --force` (переименует способы и подключит класс), добавить переменные в `.env` сервера,
`php artisan optimize:clear`, перезапустить очередь.

## Как считается доставка

| Способ (`delivery_methods.code`) | Вид отправления (`mail-type`) | Адресат |
|---|---|---|
| `russian_post_office` | `ONLINE_PARCEL` «Посылка онлайн» | отделение (ГОПС/СОПС), выбирает покупатель |
| `russian_post_courier` | `ONLINE_COURIER` «Курьер онлайн» | адрес; индекс определяет нормализация адреса Почты |
| `international_pickup` | `SMALL_PACKET` «Мелкий пакет» (до 2 кг) и `POSTAL_PARCEL` «Посылка» | страна, покупатель выбирает вариант |
| `international_courier` | `EMS` | страна |

Виды отправлений и названия лежат в `config/services.php` → `pochta.methods`, их можно менять без правки кода.

- Цена для покупателя: `total-rate + total-vat` (API отдаёт копейки), округляется вверх до рубля. Срок — `delivery-time`.
- По России передаётся объявленная ценность (сумма позиций), поэтому в цену входит страховка около 2–3 % стоимости.
  Отключить: `'declared' => false` у нужного вида отправления.
- Вес и габариты берутся у товара (правила те же, что у СДЭК: `CdekParcel`), пустые заменяет `default_package`
  (80 г на единицу, 26×21×4 см).
- Страна переводится в числовой код Почты через `config/pochta_countries.php` (ISO 3166-1 numeric).
- Ответ с нулевой ценой значит «такого тарифа нет» (так отвечает API для почтоматов и, например, EMS в Эстонию).
- При создании заказа бэкенд сам пересчитывает тариф (`revalidateCheckout`): цена и срок берутся из свежего расчёта,
  а не из запроса. В заказ пишется `delivery_data` с `provider = pochta`.
- Правил бесплатной доставки для Почты нет: все существующие правила привязаны к службам `cdek` и `yandex`.

Публичные маршруты: `GET /api/public/delivery/pochta/offices?city=…`, `POST /api/public/delivery/pochta/calculate`.

## Не проверено / что сделать

- **Почтоматы и ППВЗ.** Тарифный API аккаунта оценивает доставку на их индексы нулём для `ONLINE_PARCEL`, `POSTAL_PARCEL`
  и `PARCEL_CLASS_1` (в том числе с `delivery-point-index`), поэтому в выбор попадают только отделения. Вид `ECOM_MARKETPLACE`
  в списке доступных видов аккаунта нет. Чтобы продавать в почтоматы, нужно уточнить в Почте, как подключается ЕКОМ-доставка.
- **Этап 2: отправления.** `PUT /2.0/user/backlog` (создание заказа), формы Ф7п/Ф103, ярлыки, трек (`barcode`). Для международных
  нужна таможенная декларация (`customs-declaration`, коды ТН ВЭД). Пока заявки менеджер создаёт в кабинете Почты вручную.
- **Этап 3: отслеживание.** Отдельный API (tracking.pochta.ru), его спецификация и учётные данные не изучались.
- **Бесплатная доставка** для Почты: нужны службы в `config/free_shipping.php` и правила в админке.
- **Админка:** создание и правка заказа с Почтой России (выбор отделения на карте) пока только у СДЭК и Яндекса.
- Точка сдачи в аккаунте: отделение 188513 (Разбегаево), не Петергоф. Уточнить, что так и нужно.
