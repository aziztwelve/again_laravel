# Robokassa

Дополнительный способ оплаты в чекауте: **«Оплата SberPay, иностранная карта, Рассрочка Подели»**
(`orders.payment_method = robokassa`). Оплата открывается **в iframe-окне Robokassa поверх страницы заказа** (модальное окно, скрипт
`robokassa_iframe.js`); покупатель выбирает способ внутри окна (SberPay, иностранная карта,
рассрочка Подели и другие, подключённые к магазину). Параметр `IncCurrLabel` не передаём.

Документ создан: **2026-11-25**. Статус: **код написан локально, на сервер не залит**.

Официальная документация: <https://docs.robokassa.ru/> (разделы «Приём платежей», «Уведомления и
переадресация», «Онлайн-касса (ФЗ-54)», «Тестовый режим»).

## Как это устроено

### Поток оплаты
1. Чекаут: пункт «Оплата SberPay, иностранная карта, Рассрочка Подели» → заказ создаётся с
   `payment_method=robokassa`, `payment_status=pending`, резерв товара как у остальных онлайн-способов.
2. Страница заказа `/orders/{view_token}` показывает кнопку «Оплатить онлайн» (поле
   `robokassa_available` в публичном заказе).
3. Кнопка вызывает `POST /api/public/orders/{viewToken}/robokassa/intent`
   (`RobokassaController::intent`). Бэкенд создаёт `Payment` (`provider=robokassa`, `pending`) и
   возвращает `payment_url` и `fields` (поля формы с подписью). `InvId` = `payments.id`.
4. Витрина подгружает `https://auth.robokassa.ru/Merchant/bundle/robokassa_iframe.js` и вызывает
   `Robokassa.StartPayment(fields)` — окно оплаты открывается поверх страницы.
5. У iframe **нет колбэка о результате**, поэтому после открытия окна страница заказа сама
   перечитывает заказ раз в 6 секунд (до ~10 минут), пока он не станет «Оплачен»; тогда показывает
   уведомление и чистит корзину. Окно можно закрыть и открыть заново: каждая попытка — новый платёж.
6. Оплату подтверждает только **Result URL** (серверное уведомление): платёж → `completed`,
   заказ → «Оплачен».
7. Если после оплаты Robokassa загрузит Success/Fail URL внутри окна, бэкенд отдаёт страницу,
   которая переводит на `/orders/{view_token}?payment=success|fail` окно верхнего уровня (а не
   показывает магазин внутри модального окна). Вне окна это обычный переход.

### Адреса для личного кабинета Robokassa
Метод отсылки данных — **POST** для всех трёх.

| Поле в кабинете | Адрес | Что делает |
|---|---|---|
| Result URL | `https://again8.ru/api/webhooks/robokassa/result` | проверяет подпись (Пароль #2), сумму и платёж; помечает платёж и заказ оплаченными; отвечает `OK{InvId}` |
| Success URL | `https://again8.ru/api/webhooks/robokassa/success` | проверяет подпись (Пароль #1), переводит на заказ (из окна — верхнее окно); оплату **не** подтверждает |
| Fail URL | `https://again8.ru/api/webhooks/robokassa/fail` | переводит на заказ (см. защиту ниже); статус не меняет |

Магазин: идентификатор `again8`, алгоритм подписи MD5 (должен совпадать с `ROBOKASSA_HASH_ALGO`).

### Подписи
| Что | Формула |
|---|---|
| Запрос оплаты | `MD5(MerchantLogin:OutSum:InvId[:Receipt]:Пароль1:Shp_pay=…)` |
| Result URL | `MD5(OutSum:InvId:Пароль2[:Shp_*])`, `OutSum` берётся как пришёл (в проде 6 знаков) |
| Success URL | `MD5(OutSum:InvId:Пароль1[:Shp_*])` |

`Shp_*` сортируются по алфавиту. `Receipt` в подпись и в параметры окна идёт URL-кодированным JSON
(в демо Robokassa — `encodeURIComponent`; мы кодируем PHP `urlencode`, отличие только в записи
пробела и символов `!'()*~`).

### Защита от подбора ссылки на заказ
Ссылка `/orders/{view_token}` — секрет. У Fail URL подписи нет, поэтому при создании платежа в
запрос добавляется `Shp_pay` — HMAC от номера платежа с ключом приложения. Fail ведёт на страницу
заказа **только** при верном `Shp_pay`, иначе — на главную. Иначе перебор `InvId` отдавал бы чужие
ссылки на заказы.

### Чек 54-ФЗ
Чек передаётся в Robokassa параметром `Receipt` (`ROBOKASSA_SEND_RECEIPT=true`):
- позиции заказа: `name` (до 128 символов, без кавычек и `\`), `quantity`, `sum` (итог строки после
  скидок), `payment_method=full_payment`, `payment_object=commodity`, `tax`;
- строка «Доставка»: `payment_object=service`;
- НДС: ставка товара (`products.vat`), по умолчанию **5 %** (`ROBOKASSA_RECEIPT_VAT`) → `vat5`;
  система налогообложения (`sno`) не передаётся — берётся из кабинета;
- если часть заказа оплачена подарочной картой, разница уходит в `payments`
  (`type=1` — безналичные, `type=2` — зачёт аванса/сертификата), а не отрицательной позицией;
- если сумма позиций меньше суммы платежа, чек **не прикрепляется** и пишется предупреждение
  `Robokassa receipt was not attached: inconsistent order totals`.

### Настройки (`config/payment.php`, `.env` бэкенда)
| Переменная | Назначение |
|---|---|
| `ROBOKASSA_ENABLED` | включает способ; при `false` intent отвечает 503, кнопки на странице заказа нет |
| `ROBOKASSA_LOGIN` | идентификатор магазина (`again8`) |
| `ROBOKASSA_PASSWORD1` / `ROBOKASSA_PASSWORD2` | боевые пароли #1 и #2 |
| `ROBOKASSA_TEST_MODE` | `true` → в форму добавляется `IsTest=1`, подпись и проверка идут тестовыми паролями |
| `ROBOKASSA_TEST_PASSWORD1` / `ROBOKASSA_TEST_PASSWORD2` | тестовые пароли из кабинета |
| `ROBOKASSA_HASH_ALGO` | `md5` (по умолчанию), `sha256`, `sha384`, `sha512` — как в настройках магазина |
| `ROBOKASSA_SEND_RECEIPT` | передавать чек (по умолчанию `true`) |
| `ROBOKASSA_RECEIPT_VAT` | НДС (%) для позиций без своей ставки и для доставки, по умолчанию 5 |
| `ROBOKASSA_PASSWORD3` | ключ API возвратов (кабинет → «Технические настройки»); без него возврат из админки не работает |
| `ROBOKASSA_ALLOWED_EMAILS` | закрытый тест: email через запятую; пусто — способ доступен всем |

Пароли — только в `.env` на сервере, не в git и не в чате. После изменения `.env`:
`php artisan optimize:clear` и `pm2 restart laravel-queue`.

## Порядок выкладки (важно)

Пункт в чекауте статичный: он появляется на сайте сразу после выкладки витрины, даже при
`ROBOKASSA_ENABLED=false`. Заказ с таким способом получит резерв товара, но кнопки оплаты на нём не
будет. `ROBOKASSA_TEST_MODE` — общий для сайта: пока он включён, настоящий покупатель, выбравший
Robokassa, сделает тестовый платёж, и Result бесплатно пометит его заказ оплаченным.

Безопасная последовательность:
1. Залить **бэкенд** (и по желанию админку), в `.env`: `ROBOKASSA_ENABLED=true`,
   `ROBOKASSA_TEST_MODE=true`, логин и тестовые пароли. `php artisan optimize:clear`.
2. В админке создать **тестовый заказ** с способом оплаты `robokassa` (пункт есть в списке способов).
3. Открыть `/orders/{token}` этого заказа и пройти весь тестовый платёж: форма → Result → «Оплачен».
4. Выключить тестовый режим (`ROBOKASSA_TEST_MODE=false`), вписать боевые пароли, `optimize:clear`.
5. Только после этого залить **витрину** — и сделать боевой платёж с минимальной суммой.

Деплой — по `docs/deploy-runbook.md` и правилу «пушим все три репозитория»; админка при сборке
даёт ~80 с недоступности.

## Не проверено / что сделать
- **InvId.** Номер платежа (`payments.id`) уходит как `InvId`. Если в тесте Robokassa скажет, что номер
  уже использован, проверить, не работал ли магазин `again8` раньше со старыми способами
  (`robokassa_mokka`, `robokassa_yandex_split`) — тогда нужен сдвиг номеров.
- **Результат на реальном Robokassa не проверен.** Сначала — тестовый режим (`ROBOKASSA_TEST_MODE=true`
  и тестовые пароли) на одном заказе, затем боевой платёж с минимальной суммой.
- **Подпись с `Receipt`.** Документация противоречива (в тексте «минимизированный JSON», в примере
  подписывается URL-кодированная строка). Реализован вариант примера; если Robokassa вернёт ошибку
  подписи (код 29) только при чеке — проверить это место первым.
- **Тестовый режим на боевом сайте.** В тесте Result тоже приходит и помечает заказ оплаченным —
  включать его только на тестовом заказе, после проверки вернуть `ROBOKASSA_TEST_MODE=false`.
- **Иностранная карта.** Отдельного способа в списке магазина нет; карты иностранных банков, скорее
  всего, идут через `BankCard` — уточнить у поддержки Robokassa и включить в кабинете.
- **Лимит Podeli:** от 300 до 35 000 ₽ — вне лимита Robokassa сама не покажет рассрочку.
- **Фискализация в кабинете.** Должна быть включена облачная касса / «Робочеки»; иначе `Receipt`
  будет отклонён. Система налогообложения берётся из кабинета.
- **iframe: что не описано в документации.** Не сказано, включается ли `Receipt` в подпись окна
  (считаем, что да — как в обычной оплате), что показывает окно после оплаты и перенаправляет ли оно
  на Success/Fail URL внутри себя. На это рассчитаны ожидание оплаты на странице и страница-«выход»
  из окна; поведение проверить в тестовом режиме. Если окно не открывается, первым делом смотреть
  консоль браузера и CSP/`X-Frame-Options` на боевом nginx (в репозитории таких заголовков нет, на
  сервере могут быть): нужно разрешить скрипт и frame с `auth.robokassa.ru`.
- **SberPay и Подели в окне.** Документация не описывает, как они ведут себя в iframe (переход в
  приложение банка, мобильные браузеры). Если в тесте окно ломается на этих способах — вернуться к
  редиректу на страницу Robokassa: поля из `intent` те же, нужна только POST-форма вместо
  `StartPayment`.

## Возврат из админки

Кнопка «Вернуть оплату» в карточке заказа (`POST /orders/{id}/refund-payment`) для Robokassa работает через
API возвратов (`RobokassaService::refund`):
1. По номеру счёта (InvId) запрашиваем `OpStateExt` (подпись — Пароль #2) и берём `OpKey` — номер операции.
   Если Robokassa не подтверждает оплату счёта (код состояния не 100), возврат не делается.
2. Формируем JWT HS256 (компактный JSON) с ключом **Password3**: `OpKey` и, если при оплате передавался чек,
   `InvoiceItems` — те же позиции (Cost — цена за единицу). По документации Robokassa **чек возврата прихода
   формируется только если передан состав**.
3. POST на `https://services.robokassa.ru/RefundService/Refund/Create`, тело — JWT как JSON-строка
   (`Content-Type: application/json`). Успех → `Payment` получает статус `refunded`, `requestId` и статус заявки
   (`finished` / `processing` / `canceled`, из `Refund/GetState`) сохраняются в `provider_data.refund`.
   Повторный вызов по тому же платежу новую заявку не создаёт.
4. Заказ после успешного возврата переходит в статус «Возврат оплаты» (общая логика админки).

Нужно: **Password3** (генерируется в кабинете Robokassa → «Технические настройки») в `ROBOKASSA_PASSWORD3`.
Без него кнопка вернёт понятную ошибку, ничего не отправляя.

Не поддерживается (возврат только в кабинете Robokassa): частичный возврат; заказ, оплаченный частично
подарочной картой (состав чека возврата не восстановить автоматически).

## Способы оплаты в окне

В окне оставлены только `ROBOKASSA_PAYMENT_METHODS` (по умолчанию `BankCard,SberPay,Podeli`): `intent` отдаёт поле
`Settings` = `{"Mode":"modal","PaymentMethods":[…]}`, витрина открывает окно через `Robokassa.Render`
(`StartPayment` перезаписывает `Settings`). Скрыты СБП (есть в оплате CloudPayments), Альфа Пэй, Халва,
«Карта 120 дней», ЕРИП. Иностранные карты оплачиваются кнопкой «Оплатить картой» (идут вместе с `BankCard`).
С 27.11.2026 Robokassa не отдаёт магазину Подели (вопрос к поддержке Robokassa); вернётся в окно без правок кода.

## Сверка, отказы, срок счёта (паритет с CloudPayments и Яндекс Пэй)

| Что | Как у Robokassa |
|---|---|
| Фоновая сверка | `php artisan robokassa:reconcile` каждые 5 минут (`routes/console.php`): неоплаченные попытки старше 3 минут и моложе 3 часов сверяются с Robokassa (`OpStateExt`, состояние 100 = оплачен, сумма должна совпасть); если Result URL не дошёл — платёж и заказ помечаются оплаченными, в лог пишется предупреждение. Заодно обновляются статусы заявок на возврат (`processing` → `finished` / `canceled`). |
| Сверка по требованию | `POST /api/public/orders/{viewToken}/robokassa/status` — страница заказа вызывает его после возврата из окна оплаты (как `/yandex-pay/status`). |
| Возврат не из админки | Если по счёту состояние 60 (деньги возвращены в кабинете Robokassa), платёж получает статус «возвращён»; статус заказа не меняется. |
| Отказ / отмена | Fail URL (с верным `Shp_pay`) помечает попытку `failed`, у заказа `payment_status = failed` — заказ можно оплатить снова (как Fail-уведомление CloudPayments). Оплаченное Fail не трогает. |
| Срок счёта | В Robokassa уходит `ExpirationDate` = конец брони заказа (московское время, минуты). После автоотмены брони оплатить счёт нельзя (ошибка 33 в окне). |
| Номер счёта | Номер заказа магазина (виден в кабинете Robokassa); при повторной попытке или занятом номере — id платежа + 100 000 000. |
| Админка | В карточке заказа виджет «Платежи» показывает систему (Robokassa / CloudPayments / Яндекс Пэй), статус, сумму, состояние возврата, ошибку, номер в платёжной системе и дату — для всех способов. Страница «Интеграции → Платежи» — статичный макет без настоящих настроек (для всех систем). |

Чего у Robokassa нет по сравнению с CloudPayments: предварительной проверки перед списанием (Check) и отдельного
уведомления о возврате — вместо них сверка по `OpStateExt` / `Refund/GetState`.
